# 28 30 分钟换板清单（新人照着做）

> 目标：拿到一块新板（或同一块板换了接线），30 分钟内跑通"自检固件 → 单电机闭环"。**30 分钟是目标，不是实测**：本仓库在 PC 上把每一步跑过（换引脚到编过 7.8 s，docs/27 §1），但**没有真人拿真板计过时、没进过 Keil，标 [未测]**。
> 原则：只改引脚。`firmware/`、`apps/`、`examples/` 一行不改；改了说明走错路（`skills/dz-firmware/SKILL.md` 改法纪律）。

## 0. 准备（5 分钟，只做一次）
- [ ] 装好 STM32CubeMX（STM32）或 CCS/SysConfig（MSPM0）、arm-none-eabi-gcc 或 Keil5。
- [ ] `tools/fetch_third_party.sh`（HAL / SDK），`make check` 全绿。

## 已经有自己的 CubeMX/Keil 工程？直接导入（不用改 .ioc、不用改代码）

```sh
python3 tools/import_project.py <你的工程目录> --app car_2wd          # 先看报告
python3 tools/import_project.py <你的工程目录> --app car_2wd --accept-repair   # main.c 标记坏了时，看过 diff 再确认
make BOARD=<目录名> APP=car_2wd
```

- 板名取自目录名（自动转成合法名字）；原工程**一个字节都不改**，复制到 `boards/<名>/cubemx/`。
- **标签不用按约定改**：自动按引脚功能生成 `boards/<名>/aliases.yaml`（如 `AIN1 → GPIO_MOTOR_A_IN1`、PWMA/PWMB → MOTOR_A/B）。猜错就改这张表，`.ioc` 不动。
- **节拍定时器 CTRL**：先找 .ioc 里已开中断、没接引脚的定时器；没有就挑空闲的（TIM6/7/5/4…），由工作台自己初始化（`timer.self_init`），不用回 CubeMX 加。
- **你写在 main.c / freertos.c USER CODE 里的代码**：整块原样搬到 `user_code/from_core_user_code.c.txt`（不编译、不删），你的 APP/HARDWARE 源码备份在 `user_code/orig/`；钩子（`dz_cubemx_start/loop/tim_callback`）只插在 USER CODE 区。FreeRTOS 工程钩子放进 StartDefaultTask。
- **USER CODE 标记被改坏**（例如 while(1) 写进了 USER CODE 3 而 BEGIN WHILE 没了）：停下、打印修复 diff，确认后加 `--accept-repair`。
- **Keil(MDK) 生成的工程**没有 `*_FLASH.ld`/gcc 启动文件：按芯片从 `ports/stm32-cubemx/ld/` 模板补链接脚本，启动文件用 CMSIS gcc 模板。
- 报告分三类：动手改 / 确认 / 上板观察；`--report x.json` 输出机器可读结果。p2 Car_Mode1021：动手改 0、确认 2、观察 1；p1 Bldc：动手改 0、确认 1。
- `make` 写成 `PROJECT=` 会直接报错提示用 `APP=<目录>`。

## 1. 选起点（2 分钟）
- [ ] 下表找芯片最像的板，复制目录：`cp -r boards/<旧板> boards/<新板>`，改 `board.yaml` 的 `name:`。
- [ ] STM32 只用 `stm32-cubemx` 路线（`stm32f4-hal` 已冻结，新板会被拒绝）。

## 2. 改引脚（10 分钟）
- [ ] STM32：CubeMX 打开 `boards/<新板>/cubemx/*.ioc`，按实际接线改引脚，**User Label 保持逻辑名**（`GPIO_LED`、`PWM_MOTOR_A`、`ENC_MOTOR_A_A`…，docs/05）。
- [ ] **点 GENERATE CODE**（漏了这步编译照样过，但上电还在驱动旧引脚——`make check` 的 `check_gen_consistency.py` 会报"残留旧引脚"）。
- [ ] `python3 tools/ioc_import.py boards/<新板>/cubemx/<名>.ioc --out boards/<新板>/board.yaml --base boards/<新板>/board.yaml` 生成资源（`--base` 保留时钟、flash 等非引脚字段）；MSPM0 用 `.syscfg` + `tools/syscfg_import.py`（docs/10）。
- [ ] 芯片容量写进 `mcu.flash_kb`（链接时超了会报"程序超出本板 Flash 容量"）。
- [ ] 要掉电保存参数/黑匣子就写 `mcu.nvm_kb`（F1/MSPM0 末尾 ≥2 页；F4 只能 32/48 = 扇区 1..3）；Keil/CCS 工程不带 `-DDZ_NVM_KB` 时自动不用（ENOTSUP），想用要自己在 IDE 里把 IROM 让出这块。

## 3. 检查（2 分钟）
- [ ] `python3 tools/validate_board.py boards/<新板>/board.yaml`：0 错误；`TODO` 要么填掉，要么确认用不到。
- [ ] `make check`。

## 4. 自检固件上板（5 分钟）
- [ ] `make BOARD=<新板> APP=port_selftest`，Keil 用户见 docs/14、CCS 见 docs/15。
- [ ] 上板看：LED 闪、LINK 串口回显、定时器节拍报告正确。**任何一项不对，先查接线和 .ioc，不要改 firmware/。**

## 5. 单电机闭环（5 分钟）
- [ ] `make BOARD=<新板> APP=motor_speed_demo`（板上没 LED 用 `car_2wd`），工作台连上，给 1 r/s 阶跃。
- [ ] 电机反转 / 编码器反向：改 board.yaml 的极性字段或 .ioc 交换引脚，**不在代码里取反**。
- [ ] 结果写进 `board.yaml` 注释和 `docs/硬件路线图.md`，标【已实测】+日期。

## 为什么不给每块板复制一份 examples/<板>-minimal
docs/27 初稿建议过。否决：同一份应用复制 7 次，改一处要改 7 处，正是"屎山"。"换板只改引脚"意味着最小例程就是 `port_selftest` + `motor_speed_demo`，本清单的表格把"哪块板用哪个"写清楚，CI 保证它们一直编得过。

# 07 应用框架（project.yaml）

> 标注约定：**【已实测】** = 本仓库在 PC 上用测试/编译实际跑过（2026-10-28，Asia/Shanghai）；**【未验证】** = 设计意图或推断，尚未在真实硬件上做实验。实验是检验真理的唯一标准——【未验证】的内容上板前不要当结论。

每道题 = 一个 `examples/<题目>/` 目录：
- `project.yaml`：题目的全部“形状”——板卡角色、共享状态各段（每段**唯一写者**）、子系统（周期、owns、reads、在哪块板）、参数、参数档、测试项（小题号、限时）。
- `subsys/<名>/`：子系统实现（init/step/on_mode/selftest），**不碰硬件、不 include 其它子系统**，只读写共享状态，因此可用模拟数据单测。
- `io/`：唯一碰 PAL/驱动的胶水层：读传感器写 `io_in`，把子系统输出写到执行器。
- `tests/`：子系统模拟数据单测。

`tools/gen_project.py` 生成 project_gen.{h,c}；`firmware/framework/subsys` 调度器按周期运行；`coord` 状态机管理 IDLE/RUNNING/DONE/ESTOP/FAULT、测试项、参数档、限时，`pre_step` 钩子做跨子系统前馈。

## 示例（写法示意）
- **2026H_ball**（仓库内）：底盘 + 钢珠控制 + Jetson Nano 视觉。测试项为占位（TODO），以官方题目为准。
- **倒立摆**：`state: io_in{angle,pos} / balance_out{u}`；子系统 `balance`（1 ms，owns balance_out）、`swing_up`（5 ms）；coord 按测试项切换起摆/稳摆模式。
- **云台**：`gimbal`（1 ms，reads vision_out, imu）、`vision`（解析协处理帧）；视觉延迟补偿放 gimbal 内部。
- **多板**：project.yaml `boards: {main: ..., aux: ...}`，子系统写 `board: aux`；`gen_project.py --role aux` 只生成该板的子系统，跨板数据经 dzframe/1 传。（多板生成【已实测】于主机；多板真实通信【未验证】）

## 仿真被控对象与 link_app.h（0.11）

`apps/include/link_app.h` 把每个应用都要写的 LINK 杂事收成一个头文件：参数读写、急停锁存（'R' 解除）、单字节命令、心跳、上位机看门狗、遥测节拍，以及**设定值约定**（DATA id=1 = 1..4 个 f32，存进 `L.sp[]`）。遵守这个约定的应用，工作台的阶跃/扫频实验和 Agent 不用改代码就能用；只需在 `dzbench.json` 的 `step_tests` 里加一项（键 = 工程名，y/sp 通道、gains 对应的参数）。

新增一个仿真对象 = `apps/<名字>/` 下三个文件：`app.yaml`（requires + link 遥测/参数，状态字段加 `pin:` 进状态栏）、`app_main.c`（控制律）、`sim_setup.c`（对象模型，host_sim API）。侧车自动发现（`ports.sim_apps()`）。现有例子见 19-赛题覆盖矩阵.md 的表。car_2wd 早于 link_app.h，仍是自己的一份收发代码（行为相同，未迁移）。

换板子时 requires 不满足会在编译前报 `[缺资源]`（0.11 起每个 板×应用 单独检查；之前换 APP 可能跳过检查、变成 `RES_xxx undeclared` 编译错误）。

## 子系统库入库规则
1. `tools/new_subsys.py` 生成骨架（VERSION 0.1.0）。
2. 在至少一道题中**实际上板**使用并记录结果后，才可提到 1.0.0、迁入公共子系统库；README 写明接口（reads/owns 字段）、参数、实测平台与日期。
3. 满足 04 清单。

- 【已实测】2026H_ball 主机闭环仿真与子系统单测通过；交叉编译到 skystar/skystar-cubemx 通过。
- 【未验证】控制参数（kp/ki/kd、mm_per_px 等）均为占位值。

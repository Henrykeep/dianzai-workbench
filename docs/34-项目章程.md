# 电赛工作台 · 项目章程（据用户原话整理，2026-10-31）

## 一、初衷 / 宗旨
- 初衷（10/28）：大三、要备考研，想要"一套很成熟的方案，能够让我快速的完成这个项目的百分之90以上的事情"，同时保证质量。
- 适用范围（10/31）：工作台"专门为了电赛或者开发嵌入式项目做的"，不只为电赛。
- "可移植可复用性是重中之重！！！"：工程交给别人"改一些引脚啥的就能快速复用"，也能做下一个项目的底座，不能"让ai改的面目全非"。
- 宗旨（用户反复强调）：带脑子思考、顾全大局；不堆屎山；站在用户角度想（从拿到题目到比赛结束）；站在巨人肩膀上（善用搜索、学参考仓库，"学到精髓，不要半吊子"，模仿借鉴而不是抄袭）；客观分析、客观对待；创新"只是一个选择"，必须实践验证。
- 目标："尽量把工作台打造全能，代替人做完99%"（10/30），"能帮我干的尽量干完！而且要干好"。

## 二、硬性要求
- 做桌面 exe，不做 web 应用：调 PID、DMA 收发都要让工作台直接拿到数据。
- CubeMX + HAL 库；常用 Keil5，TI 板用 CCS，可以加别的 IDE。ST-Link、DAPLink、J-Link 都要支持。
- 板卡：C8T6、天空星 407、天猛星 3507 是常用的，但"不能只做这三块"；FreeRTOS 以后会用；FPGA 放到后面。
- 内置 Agent 要好好做，"成为我的得力助手"。
- 有可能没有现成工程，要能从零新建。
- 有用但不在主线上的功能放进工具箱。
- 做好版本管理；CI 不能老是失败。

## 三、界面原则
- "要高级美观而且好用"，"要有一个工作台的样子"，要有"大厂的高级感、企业产品那种质感"。
- 用户觉得当前排版"杂乱""不高级"；"紫色也太难看了"。
- 不要照着参考图套，按功能逻辑设计，界面"不要受束缚"。功能逻辑变了，界面也跟着变。
- "你不要我说什么就是什么"，要自己去把控。
- 不要找用户要参考图；参考（如服务器监控面板）只学质感不照抄（10/30 用户批评过照搬图片）。

## 四、工程规矩
- 用户原话："不要停下来，除非我让你们停。"
- 按初衷走；不能"只针对26年这道题"，要"是一个体系，应万变"。
- 以下由 agent 制定，用户没有异议：每人用独立 worktree；推送前先 rebase 并跑通 check/preflight；不强推；公开仓库里不放密钥。

## 五、用户明确不要的东西
屎山；web 应用；专为某道题写的代码；抄袭；半吊子学习；不用 HAL、自己从寄存器手写的不可复用代码；紫色；杂乱的排版；凡事要用户反复提醒；照搬用户自己的坏习惯（"你要客观！"）。

## 六、未决事项
- 用户最新反馈："很不满意"，"ui 排版不好看"，还没有具体到哪一页。
- "九成工作量"还没有度量（make bench 在做）。
- 真机验证、Windows 安装包测试，需要用户的电脑。
- FPGA 和 FreeRTOS 的排期。
- 视觉协议和电机驱动由 agent 按最优方案自定，用户说"按最优的来"。

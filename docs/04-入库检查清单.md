# 04 入库检查清单

> 标注约定：**【已实测】** = 本仓库在 PC 上用测试/编译实际跑过（2026-10-28，Asia/Shanghai）；**【未验证】** = 设计意图或推断，尚未在真实硬件上做实验。实验是检验真理的唯一标准——【未验证】的内容上板前不要当结论。

## A. 自写模块入库（版本达到 1.0.0 之前逐项打勾）
- [ ] 三件套齐全（03）；README 写清【已实测】/【未验证】和参考来源
- [ ] 只依赖允许的层（`make check` 通过）
- [ ] 无 malloc、无 printf、无 double、无阻塞延时（控制路径）、无全局可变状态（状态放在调用者传入的结构体里）
- [ ] 所有输入做参数检查（空指针、NaN、越界）并返回 dz_err_t
- [ ] 主机单测覆盖正常 + 边界 + 错误路径；`make test` 通过
- [ ] 需要硬件的结论：写明哪块板、哪天、怎么测、结果（附波形/日志）。没有实测就标【未验证】
- [ ] 子系统：只读写 project.yaml 声明的段；有模拟数据单测（`tools/new_subsys.py` 生成骨架）

## B. 第三方代码移植入库（配合 `tools/audit_port.py`）
1. 放在 `third_party/<名字>/` 或模块目录，保留原 LICENSE，新建 `SOURCE.md`：上游地址、commit/tag、许可证、改了什么。
2. 运行 `python3 tools/audit_port.py <目录>`（命令行审计按第三方代码处理，含 A9；自检中对自有 pid 模块不查 A9），处理报告：
| 规则 | 检查 | 处理方式 |
|---|---|---|
| A1/A2 | 厂商头文件/调用 | 换成 PAL 调用 |
| A3 | 直接寄存器访问 | 换成 PAL；确需保留放进 ports 并写 DZ-REG-OK |
| A4 | 阻塞延时 | 改为状态机/定时回调 |
| A5 | malloc/free | 改为静态分配或调用者提供内存 |
| A6 | printf 等 | 删除或改为可选日志钩子 |
| A7 | double | 改 float（Cortex-M4F 只有单精度 FPU） |
| A8 | 自定义 IRQHandler | 中断入口归移植层/CubeMX |
| A9 | LICENSE/SOURCE 缺失 | 补齐 |
| A10 | 三件套缺失 | 补 README/VERSION/selftest |
3. 包一层符合 03 的接口，写主机单测后再入库。
- 【已实测】`audit_port.py --selftest`：故意写坏的 fixtures/audit_bad/oled.c 触发 A1–A10 全部规则；自有 pid 模块无高/中风险项。

# 11 中断与实时准则

> 标注约定：**【已实测】** = 本仓库在 PC 上用测试/编译实际跑过（2026-10-28，Asia/Shanghai）；**【未验证】** = 设计意图或推断，尚未在真实硬件上做实验。实验是检验真理的唯一标准——【未验证】的内容上板前不要当结论。

1. 中断入口（xxx_IRQHandler）只属于移植层/CubeMX；上层通过 `pal_timer_start` 回调或主循环轮询。
2. 回调里只调用 `[ISR-safe]` 函数；不阻塞、不 printf、不 malloc，执行时间 ≪ 周期（建议 < 20%）。
3. 控制环推荐：定时器回调只置标志或做最短的采样+计算+输出；调度器 `subsys_sched_poll` 在主循环运行。
4. 主循环与中断共享的变量：`volatile` + 短临界区（`pal_irq_save/restore`），或单写者 + 原子宽度（32 位对齐）。
5. 时间比较一律用差值 `(now - then) >= period`，自然处理回绕。
6. 优先级：分组 4；控制定时器 > 串口 DMA > SysTick 之外的其它；HAL 时基 SysTick 优先级须能在其它中断中让 HAL_Delay 工作（但框架内不在中断里延时）。

- 【已实测】调度器回绕、overrun 统计主机单测。
- 【未验证】真实 MCU 上的中断延迟、抖动；需用逻辑分析仪/GPIO 翻转实测后再定周期上限。

## FreeRTOS（可选，config_source.rtos: freertos 的板子）
裸机是默认；需要多任务时用 CubeMX 开 FreeRTOS（CMSIS_V2），HAL 时基改 TIM（见 docs/05）。框架给三样东西：

1. **周期任务模板** `ports/stm32-cubemx/freertos_task_template.c`：任务入口只写 `dz_rtos_periodic(&task)`，内部用 `vTaskDelayUntil`（不漂移），记录运行次数、超时次数（超时后重新对齐，不连环补跑）和单次最长耗时。
2. **栈余量遥测**：`dz_cubemx_loop()` 在 FreeRTOS 板上自动调用 `dz_rtos_monitor_poll()`（500 ms 一次，`uxTaskGetSystemState`），把所有任务里最小的栈余量和任务名写进 `g_rtosmon`（firmware/framework/rtosmon）。2026H_ball 遥测通道 `stk_min_w`（单位：字，4 字节）。低于 32 字就该加栈。
3. **CPU 负载通道**：CubeMX → FREERTOS → Config parameters → `GENERATE_RUN_TIME_STATS = Enabled`；需要的 `configureTimerForRunTimeStats / getRunTimeCounterValue` 已在 `dz_freertos.c` 用 DWT 周期计数器实现。遥测通道 `cpu_pm`（千分比）= 1 − 空闲任务时间占比。没开运行时统计或裸机板 → 0xFFFF（无数据）。

- 【已实测】rtosmon 换算主机单测；stm32f407-bldc-freertos-cubemx/2026H_ball 交叉编译、链接通过。
- 【未测】上板读数。上板后用 Keil/Cortex-Debug 的 RTOS 视图或 `vTaskGetRunTimeStats` 对照一次。DWT 计数在 168 MHz 下约 25 s 回绕一次，采样间隔 500 ms，差值算法不受影响。

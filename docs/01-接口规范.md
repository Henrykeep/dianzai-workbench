# 01 接口规范（PAL）

> 标注约定：**【已实测】** = 本仓库在 PC 上用测试/编译实际跑过（2026-10-28，Asia/Shanghai）；**【未验证】** = 设计意图或推断，尚未在真实硬件上做实验。实验是检验真理的唯一标准——【未验证】的内容上板前不要当结论。

## 1. 原则
1. 上层（算法、驱动、子系统、应用）只通过 `firmware/pal/pal.h` 访问硬件；**换板只改 `BOARD=`**。
2. 资源用**逻辑 ID**（`RES_LED`、`RES_PWM_MOTOR_A`…），由 `boards/<板>/board.yaml` 生成到 `board_gen.h`。代码里不出现引脚号。
3. 所有函数返回 `dz_err_t`：0 成功，负数失败（`firmware/common/dz_err.h`）。
4. 不在 PAL 里分配内存、不阻塞（`pal_delay_*` 除外，只在初始化用）。
5. 标 `[ISR-safe]` 的函数可在中断回调里调用，其余只在主循环/初始化用（见 11-中断与实时.md）。

## 2. 接口一览
| 类别 | 函数 |
|---|---|
| 系统 | `pal_init`、`pal_irq_save/restore`、`pal_millis/micros`（回绕安全，比较用差值）、`pal_delay_us/ms` |
| GPIO | `pal_gpio_write/read/toggle`（逻辑电平 active，极性在 board.yaml） |
| PWM | `pal_pwm_set_duty`（0..PAL_DUTY_MAX）、`pal_pwm_set_pulse_us`（舵机）、`pal_pwm_get_freq` |
| 编码器 | `pal_enc_get_count`（移植层扩展到 32 位）、`pal_enc_reset` |
| 串口 | `pal_uart_write`（非阻塞，上一帧未发完返回 EBUSY）、`pal_uart_tx_idle`、`pal_uart_read`（环形缓冲）、`pal_uart_rx_dropped` |
| 定时器 | `pal_timer_start(id, period_us, cb, ctx)`、`pal_timer_stop` |
| ADC | `pal_adc_read`、`pal_adc_info`（位数、参考电压） |

## 3. 错误码
| 码 | 值 | 含义 |
|---|---|---|
| DZ_OK | 0 | 成功 |
| DZ_EINVAL | -1 | 参数非法 |
| DZ_ENODEV | -2 | 本板无此逻辑 ID |
| DZ_EBUSY | -3 | 资源忙（如 DMA 发送未完成） |
| DZ_ENOTSUP | -4 | 本移植层不支持 |
| DZ_ETIMEOUT | -5 | 超时 |
| DZ_ESTATE | -6 | 调用顺序错误 |
| DZ_EIO | -7 | 底层失败 |
| DZ_EFAIL | -8 | 自检失败等 |

固件 `main` 在 `pal_init`/应用初始化失败时 LED 快闪（10 Hz），用调试器看错误码。

## 4. 验证状态
- 【已实测】host-sim 实现通过全部主机单测（`make test`：178 项，ASan/UBSan）。
- 【已实测】stm32f4-hal、stm32-cubemx 实现能交叉编译（arm-none-eabi-gcc 13.3）。
- 【未验证】两个 STM32 实现在真实板子上的任何行为（时序、DMA、PWM 波形、编码器方向）。

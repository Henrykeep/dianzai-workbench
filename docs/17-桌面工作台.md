# 17 桌面工作台（dzbench）

> 场景：比赛现场、时间紧、队友第一次用。目标是**插上就能看曲线、改参数、随时急停**，出错时告诉你怎么修。

## 一分钟上手
```bash
pip install -r app/sidecar/requirements.txt          # pyserial websockets pytest
(cd app/ui && npm ci && npm run build)
PYTHONPATH=app/sidecar python3 -m dzbench --ui app/ui/dist   # 浏览器打开 http://127.0.0.1:8766/
```
- 没有硬件：端口选 **仿真板 · <工程名>**（apps/ 与 examples/ 下有 sim_setup.c 的都会自动列出：car_2wd、motor_pos、pendulum_rot、pan_tilt、line_car、2026H_ball……；host-sim 跑真实固件逻辑，自动 `make`），界面与真板完全一样。
- 有硬件：插 USB 转串口，端口会自动出现并选中；波特率默认“自动”。
- Windows 安装包：`.github/workflows/app-windows.yml` 手动触发（**未测**，见下文）。

## 界面导航（按比赛时间线）
顶栏一排 8 步：**项目 → 烧录 → 模块 → 联调 → 标定 → 调参 → 评分 → 封箱**，点一步切到那一页，旁边一行字写“当前：… · 下一步：…”（下一步那格有下划线）。不管在哪一页，右上角始终有 **排障**（自检、读黑匣子）、**工具箱**、**急停 / 解除**，左上角始终是连接。
| 页 | 放什么 |
|---|---|
| 项目 | 引导流程：① 读题（拖题目 PDF）→ ② 方案选型 → ③ 导入你的 CubeMX/Keil 工程 → ④ 资源分配 → ⑤ 生成工程 / IDE 文件；每步“运行”只在暂存区，“确认写入”才写 |
| 烧录 | 调试探针…、编译、烧录…、回滚固件… |
| 模块 | 原始收发 + 发送 + 常用指令、板端命令、ELF 变量 |
| 联调 | 示波 / 频谱 / 事件时间线、A/B 光标 |
| 标定 | 标定向导：0 极性 → 1 循迹黑白 → 2 FOC 对齐 → 3 IMU 零偏 → 4 视觉像素表；右边是标定的提议卡 |
| 调参 | 左：曲线；中：参数（下发 / 撤销 / 快照）；右：Agent 助手；底部：**实验**（阶跃、扫频、仿真搜索、分析阶跃、调参前问答、规则建议）、**判定**（改参 → 阶跃 → 判读 → 定稿）、**回到…**（最好一轮 / 某个快照 / 恢复固件默认 / 撤销 Agent / 烧前固件） |
| 评分 | 左：曲线；右“评分”栏：评分项矩阵（评分项 / 自动判定 / 人工证据 / 当前结论），选一项跑 N 轮（按钮或遥测条件开始），自动计时 + 到位判定 + 最差一轮，存证据（CSV + 曲线截图） |
| 封箱 | 赛前全绿检查（含存参数到 flash、导出封箱清单）、回读参数文件、写回 yaml |

工具箱：波形测量、串口线控、非工作台帧格式、记录（回放 / 导出 / 导入）、协处理器部署、大模型设置、切换主题。每个按钮只在一个地方出现，登记在 `docs/dev/entrypoints.yaml`（`make check` 检查）。

## 架构
```
 ┌──────── Tauri 外壳（只开窗、拉起/收掉侧车）────────┐
 │  UI：Vite + TS + uPlot（app/ui）                    │
 └───────────────▲─────────── WebSocket JSON ─────────┘
                 │ ws://127.0.0.1:8765
 ┌───────────────┴──── Python 侧车 dzbench（app/sidecar）────────────────┐
 │ transport（串口 / sim:<app> / 回放） → dzlink.Parser → session          │
 │ schema（按心跳哈希匹配 link_schema.json） downsample（min-max 60 Hz）   │
 │ logfile（.dzlog 原始全量）snapshots  agent_api（只读 + 提议）           │
 └───────────────▲──────────────────────────────────────────────────────┘
                 │ dzframe/1（与固件同一实现：host/python/dzlink）
       板子：dzctl（参数表/限幅/急停锁存）+ link_gen（gen_link.py 生成）
```
- 协议逻辑全在侧车，可脱离界面用 pytest 测；界面只是渲染 + 按钮。外壳坏了也能用浏览器模式。
- 侧车不抽稀地把原始字节写进 `~/.dzbench/logs/run_*.dzlog`，给 UI 的才抽稀（每 16 ms 每通道 ≤200 点，桶内取 min/max，毛刺和超调峰值不丢）。

## 板端协议（dzctl，firmware/proto/dzctl）
| 帧 | 方向 | 内容 |
|---|---|---|
| HEARTBEAT | 板→PC 500 ms | u32 schema 哈希（FNV-1a32，gen_link.py 生成） |
| DATA id=遥测 id | 板→PC | link.telemetry 字段（小端紧凑） |
| PARAM_SET id=参数序号 | PC→板 | len 0 = 读；len 4 = 写 f32 |
| PARAM_ACK | 板→PC | u8 状态（0 OK/1 CLAMPED/2 BAD_ID/3 BAD_LEN/4 BAD_VALUE）+ f32 实际值 |
| DATA 0x7F | PC→板 | 急停（锁存，直到 CMD 'R'） |
| DATA 0x7E | PC→板 | 命令：u8 字符 [+ u8 参数] |

参数协议借鉴 MAVLink 参数微服务（按索引读写、写后回显实际值）与 PX4 参数元数据（min/max/unit 在生成期给出）。

## WebSocket 协议（app/sidecar/dzbench/server.py）
UI→侧车 `{"op", "rid", ...}`，回 `{"type":"reply","rid","ok","data"|"error"}`。错误统一为 `{code, message, fix}`，界面原样显示“怎么办”。

| op | 说明 |
|---|---|
| hello / list_ports | 端口（串口 + 仿真板）、当前状态、schema、参数、快照 |
| connect {port, baud:"auto"\|数字} / disconnect | 自动波特率：依次试 460800、921600、115200…每个听 250 ms，收到合法帧即停 |
| estop | 连发 3 帧；未连接/回放中**如实**说没送达 |
| cmd {c, n} / send_data {id, hex} | 板端命令 / 应用自定义 DATA（如 car_2wd 轮速设定） |
| param_set / param_read_all | 侧车先限幅，再等 ACK（250 ms × 3 次重发） |
| snapshot_save / snapshot_list；恢复统一走 params_restore {source: default\|snapshot\|best, name, ramp_s} | `~/.dzbench/snapshots/<哈希>/`，换固件不会串 |
| log_list / replay {path} | 回放走同一条解析路径 |
| propose / proposal_decide / agent_tool | Agent 接缝（下节） |
| raw_monitor {on} | 开/关原始监视器推送 `raw`：`c=[[t, 方向 0收/1发, hex]...]`，每 1/60 s 最多 16 KB，积压超 256 KB 丢最旧并计入 `raw_dropped` |
| auto_reconnect {on} | 串口意外断开后按 0.25/0.5/1/2/4 s 退避重开同一口；主动断开/仿真/回放不重连；重连成功推 `reconnected` 并重读参数 |
| fft {field, seconds} | 频谱：取最近 seconds 秒，按 schema `telemetry.period_ms` 定采样率（与实测间隔差 >20% 或有丢帧会警告），去直流、Hann 窗、N=2 的幂 ≤4096，单边幅值已做窗修正；返回前 3 个峰 |
| replay_ctl {seek, speed, pause} | 回放时间轴：跳到第 seek 秒（清旧样本，推 `seeked`）、0.05–20 倍速、暂停 |
| log_export {path} | .dzlog → 同名 .csv（UTF-8 BOM、`t_s` + 各字段，枚举多一列文字） |
| tune_analyze / agent_ask / yaml_writeback / change_decide / rollback … | 内置 Agent，见 docs/18 |

推送：`status`(4 Hz)、`telem`(60 Hz)、`schema`、`param`、`proposal`、`error`、`estop`、`raw`、`reconnected`、`change`、`agent_tool`。

## Agent 接缝（Agent 本体见 docs/18）
`agent_api.AgentTools`：`read_telemetry(seconds)`、`list_params()`、`propose_param_change(name, value, reason)`。
- 工具定义是 JSON Schema（`TOOLS`），可直接映射为 MCP / function calling。
- **Agent 不能直接写参数**：提议变成界面卡片，人点“采纳”后走与手动修改相同的限幅/ACK/日志路径；急停只属于人。测试 `test_websocket_server` 断言了“提议不生效，采纳才生效”。

## 界面要点
- 急停：右上红键，`Space`（不在输入框时）或 `Esc`（任何时候）；侧车断开时也能点，并提示“未送达，立刻断电”。
- 参数：改了没下发的格子是橙色；`Enter` 下发单项，`Ctrl+Enter` 全部；`↑/↓` 按量程 1% 微调（Shift ×10）；超范围先在界面限幅并提示，板端还会再限一次。
- 快照：`Ctrl+S` 存、列表一键恢复、“恢复默认”= 固件编译时默认值。
- 曲线：2/5/10/30 s 窗口、`P` 暂停、点通道名开关；枚举通道（如 `state`）以文字显示。
- 新插的串口自动选中并提示；ttyS0/COM1 这类板载口不默认选。
- 原始视图：曲线面板右上“原始”，文本/HEX 切换，非工作台固件的设备（视觉模块 printf、蓝牙 AT）手动选波特率连上即可看。
- 线松了：自动重连，链路显示“重连中…”；此时急停送不到板子（板端应靠心跳超时自停，见 dev/QUESTIONS.md 决定 1）。
- 频谱视图：曲线面板右上“频谱”，选通道和窗口，峰值标出频率——振荡 3 Hz 还是 25 Hz 决定了是减 Kp 还是查机械/滤波。
- 回放：底栏时间轴可拖动、暂停、倍速。
- 底栏“导出”：选中的记录按下拉格式导出（CSV Excel 带 BOM / PlotJuggler .pj.csv / VOFA+ FireWater .vofa.txt）；没有 schema 的文本记录也能导。
- 连接栏“线控…”：连着时拨 DTR/RTS、ESP32 / STM32 一键复位与进下载、看 CTS/DSR、串口卡死检测（秒）。
- 底栏“导入…”：CSV 或 VOFA+ FireWater 文本 → `~/.dzbench/logs/import_*.dzlog`，马上回放（`dzbench/logio.py`，op `log_import`）。
- 曲线区“分格 / 按单位 / 叠加”：每通道一格、同单位合一格、全部叠一格（共用 Y 轴）。
- 保护阈值表（参数区“保护”页，`ui/src/protect.ts`）：列出 app.yaml 里带 `protect: 分类` 的参数（如 `protect: 倾倒角`、`限幅`、`断线停车`、`堵转电流`）和 `link.protect_fixed` 里的编译期常量（如看门狗 ms，只读，标出在哪改）。改值与参数面板共用草稿 → Enter 下发；每次下发记下发前的板上值（每参数 10 次），“撤销”把它再下发一次。`protect` / `protect_fixed` 不进 schema 哈希，加分类不用重烧。
- 赛前检查（侧栏 ☑ 按钮，`dzbench/precontest.py`，op `precontest` / `precontest_export`）：自检（电脑）+ 板子（在线、固件 = 当前固件源码（板上那次提交之后 firmware/ports/apps/boards/examples/third_party/tools/Makefile 没改、也没有未提交改动；只改文档/上位机仍算一致；勾“严格”= 必须就是 HEAD；带“+改动”烧的一律 ✗）、板上参数 = 固件默认值、急停未锁、无未确认严重告警、最近 60 s 0 坏 0 丢）+ 工程（工作区已提交），全部 ✓ 才显示“全绿”。只读。“导出封箱清单”写 `~/.dzbench/seal/封箱-<时间>.md`：结论、板 ID / 固件版本 / 参数表哈希 / 仓库提交、每项结果与处理、板上参数表、人工确认空框（电池、螺丝、线束、急停实按、备件、固件拷 U 盘）和签字栏。
- 告警条（底栏上方，`ui/src/alerts.ts`）：时间线里的严重事件（急停、看门狗、CRC 突增）一直挂着，显示条数和最新一条（点它跳到那一刻），直到点“知道了”。确认位置记在侧车（op `alert_ack`，广播 `alert_ack`），所以多个窗口、刷新页面都一致，已确认的不会再弹。
- 链路心跳条（底栏，`dzbench/linkhealth.py` + `ui/src/hbstrip.ts`）：每格 1 秒，绿=正常、黄=帧率掉到近 30 s 中位数一半以下、红=这一秒有 CRC 坏帧或 seq 缺口丢帧、灰=没帧；悬停看 帧/s · 坏帧 · 丢帧 · kB · dzlog 时间。点格子：回放时按 dzlog 时间跳到那一秒前 1 s；实时时暂停曲线、视图移到那一秒并落 A 光标（已滚出缓冲就提示 dzlog 时间，去回放里点）。只看 dzframe 层计数和板子 seq，任何对象通用；seq 缺口 ≥128 当作板子复位不算丢帧。status 消息带新收的格子 `hb`，op `health` 取全部（最多 600 格）。
- 事件时间线（曲线下方，`dzbench/events.py` + `ui/src/timeline.ts`）：连接/断开/重连、参数下发（板子 ACK）、急停、看门狗（连着时 1.6 s 没心跳，板端应已自停）、CRC 突增（1 秒 ≥3 且 ≥ 前 30 秒均值 3 倍）、阶跃实验完成、Agent 采纳（提议/改动）。每条带 dzlog 时间和曲线时间，曲线上画虚竖线；点一条与心跳条同样跳转。分类在 server 唯一出口（广播 + op 回复）按表做，加一类事件 = events.py 加一行；op `timeline` 取最近 2000 条。

### 发送与预设（批次 3，思路参考 SerialWeb，代码自写）

| op | 说明 |
|---|---|
| `send_raw` `{text}`/`{hex}` | 原始发送，≤1024 字节 |
| `preset_list/save/delete/send` | 预设：text(+换行) / hex / cmd(不能是 R) / data(id+HEX)，存 `~/.dzbench/presets.json` |
| `preset_timer` `{name,on,period_ms≥10,count}` | 定时发送，侧车线程里跑 |
| `preset_trigger` `{name,on,field,op_,value,cooldown_ms}` | 遥测满足条件时发一次（上升沿 + 冷却） |

- **急停后**：全部定时/触发立即停掉（不是暂停），侧车的 send_raw/send_data/预设一律拒发（`tx_locked`），点“解除急停 R”或重新连接才恢复；推送 `tx_locked` / `sender`。
- **文本遥测**：设备没有 dzlink 心跳时，`key=value` / `key:value` 行（逗号/分号/空格分隔）自动生成虚拟 schema（hash `TEXT`，最多 16 字段），曲线、FFT、触发都能用。
- **自定义帧结构**（连接设置“非工作台帧”）：VOFA+ JustFloat（N 个 f32 小端 + 帧尾 `00 00 80 7F`）、FireWater（`名字:1,2,3\n`），或自定义 JSON：`header`/`footer`（十六进制，至少一个）、`fields[{name,type,scale}]`（u8/i8/u16/i16/u32/i32/f16/f32/f64）、`endian`、`checksum`（none/sum8/xor8/crc8/crc16_modbus）+ `check_from`。校验错/帧尾不对的帧丢掉、从下一字节重找头；侧车 op `framedef_set {def}` / `framedef_status`（含错帧数）。实现 `app/sidecar/dzbench/framedef.py`，测试 tests/test_framedef.py。[仿真]
- **仿真搜索**（Agent 栏）：开环下给控制量一个台阶，点“仿真搜索”填反馈/控制量通道和策略（`pso` / `staged`，加 `,wide` 为宽范围）。侧车 op `tune_search {y,u,seconds,strategy,wide,top_k}`：辨识 FOPDT（identify.open_loop_pid）→ 在模型上仿真搜索（PSO / 分阶段，净室实现，算法来源见 docs/参考来源.md，`dzbench/tuning/search.py`）→ top-k。候选不写板子；“上板验证”发 `propose {changes, source}` 提议卡（规则建议 / 分析阶跃 / 仿真搜索都走这一个 op），你确认后才限幅写入；卡片上勾“全部采纳后自动做一次阶跃实验”（默认勾），整组采纳后自动阶跃并显示 TuneGuard 判定，有一张被拒就不做。PSO 只在仿真里跑。[仿真]
- **快照标签 + 平滑切换**（快照页）：存快照时可选“速度环 / 位置环”标签（只是标签，不切换固件环结构）；恢复时填过渡秒数（0 = 一步写），侧车每 50 ms 线性插值一步、最后一步回读校验，急停立即停写。op `snapshot_save {name,mode}` / `params_restore {source:"snapshot",name,ramp_s}`。固件若有环结构开关（如 `loop_mode`），把它当普通参数存进快照即可。
- **参数生命周期条**（参数页顶部）：草稿（N 待下发）→ 板上 RAM（N 个≠默认）→ 快照（N 个）→ flash → app.yaml，点一格跳到对应入口；“自动-最好一轮”不在快照列表里重复出现，只从“回到… → 最好一轮”进。发送栏的“存”现在叫常用指令。[仿真]
- **最好一轮 / 回滚 / 步长**：每次阶跃实验后护栏的最好一轮自动存成快照“自动-最好一轮”；调参页底部“回到… → 最好一轮”弹确认框后写回；`dzbench.json` 里 `tune.max_step_ratio`（如 0.2）把每步相对变化限到 ±20%（只收紧，不会放宽实机档位的 +50%/−30%）。[仿真]
- ⚠ 以上只在假串口单测（app/sidecar/tests/test_batch3.py）验证过，**未上真机**。

## 项目页引导流程（项目页）

**第 ③ 步分叉：导入已有工程 / 从零新建。** 工程目录留空时，第 ③ 步列出“芯片 × 接线模板”候选（方案主控排第一，F1/F4 能生成；MSPM0 要先在 SysConfig 里配好再导入）。默认第一项自动预览：`tools/alloc.py` 分配引脚 / 定时器 / DMA → `tools/gen_ioc.py` 生成 CubeMX 工程 `.ioc`（工具链 MDK-ARM）→ `tools/ioc_import.py` 反导核对。确认后写到 `~/dz-cubemx/<板>/<板>.ioc`。**要人做的只有一下：用 CubeMX 打开它、点 GENERATE CODE**（本机跑不了 CubeMX 代码生成）；页面轮询到 `Core/Src/main.c` 就自动接着导入，之后同“导入已有工程”。命令行等价：`python3 tools/alloc.py scheme.yaml -o out --name <板>` 再 `python3 tools/gen_ioc.py out/board.yaml -o <目录>/<板>.ioc`。

**从零新建不用等外部工具（现状）。** STM32：确认后除 `.ioc` 外还写一份合成 Core（`tools/gen_core.py <alloc/board.yaml> <目录>`，标“非 CubeMX 输出”），页面立刻自动导入、能直接 `make`；有 CubeMX 时打开 .ioc 点 GENERATE 覆盖再重跑导入（推荐上板前做）。MSPM0：`tools/gen_syscfg.py <alloc/board.yaml> boards/<板>`，需要 TI SysConfig CLI（`~/ti/sysconfig_1.28.0/sysconfig_cli.sh` 或 `SYSCFG_CLI`，TI 官网免费）和 `third_party/mspm0-sdk`；没装时 MSPM0 候选灰掉并写原因。候选列表先用 alloc 试跑，装不下的排在后面并写“装不下：…”。第 ⑤ 步确认后自动 `make BOARD=<板> APP=<应用>`，通过后出 IDE 工程：`tools/gen_eide.py --board --app`（EIDE，boards/<板>/eide/<应用>/），MSPM0 另有 `tools/gen_ccs_projectspec.py` 和 `tools/gen_m0_keil.py`（boards/<板>/keil/）。EIDE / Keil / CCS 工程都未在对应 IDE 里打开过。

每步两个按钮：**运行**在暂存区 `~/.dzbench/flow/<题号>/stage/<步>/` 跑仓库里现成的命令行工具，命令和输出原样显示；**确认写入**才写到题目目录（默认 `examples/<题号>/`，可改）/ `boards/<板名>/` / `build/<题号>/gen/`。侧车 `dzbench/projflow.py`，op `flow_preview` / `flow_accept` `{step: req|scheme|import|alloc|gen, code, dest, …}`。

1. **读题**：拖题目 PDF（或 .txt）→ `tools/req.py init` 起稿 → 评分项表格（编号 / 基本发挥 / 分值 / 原文可改、可删）→ 确认写 requirements.yaml。req.py 只切分文字、抓数字单位，分值和指标要人对照原文填；空格子不写字段。
2. **方案选型**：`tools/scheme.py --init-scheme` + 候选表 options.md；scheme.yaml 在文本框里改 picks / reasons → 确认写 scheme.yaml（和 scheme/ 下的 options.md）。
3. **导入你的工程**：填 CubeMX / Keil 工程目录（有 .ioc 的那层）和板名 → `tools/import_project.py` 导到暂存根（仓库其它目录是符号链接，boards/ 是暂存副本，原工程只读）。main.c 的 USER CODE 标记坏了会先显示修复 diff，点“接受修复并重跑”（`--accept-repair`）；然后显示自动别名表（引脚 → 逻辑名，原标签在说明列），改右列 → 确认才复制到 `boards/<板名>/`；已存在要勾“覆盖”。
4. **资源分配**：`tools/alloc.py`，有第 3 步的板子就带 `--fixed boards/<板名>/board.yaml`（已焊死的接线沿用）→ 显示 alloc.md / board.yaml / cubemx.md → 确认写 `alloc/`。
5. **生成工程 / IDE 文件**：题目目录有 project.yaml 才跑 `tools/gen_project.py`（没有就提示用 new_subsys 起稿，见 docs/07）；填了 .uvprojx（还要板名 + 应用）再跑 `keil_inject --dry-run` 显示改动，确认后真改（keil_inject 自己备份 .uvprojx.bak）。

少按键（真实工程走查后加的，都是通用规则）：确认一步后自动跑下一步的“运行”（预览只写暂存区）；第 ③ 步工程目录填完（change）就自动运行，同一目录失焦不重跑；题号空着时按 PDF 文件名猜（“H题_…” → 当年 + H，“2025E…” → 2025E）；板名默认取工程目录名去掉“副本 / copy / (6)”，剩不下就用 .ioc 文件名；工程里的 .uvprojx（根目录或 MDK-ARM/）自动填进第 ⑤ 步；导入确认后应用默认 port_selftest（import_project 自己建议的下一步），所以没有 project.yaml 时第 ⑤ 步也能先把板卡自检模块注入 Keil（gen 本身仍显示退出码 1 和 new_subsys 提示）。

第 ② 步不用改文本：侧车调用 tools/scheme.py 的 needs_of / candidates，每个能力标签一行下拉框（按仓库支持程度 上板 > 仿真 > 编译 > 无驱动 排序，默认第一名，规则禁用的单列 ✗），主控一行，理由可填；确认时把选择写进 scheme.yaml 的 picks / reasons / mcu。原始 scheme.yaml 收在“直接改”里。

第 ⑤ 步没有 project.yaml 时自动起稿：能力标签 = requirements 的 needs ∪ scheme 的 picks（去掉 offboard），和 `tools/catalog/subsys_catalog.yaml` 里每个现成子系统的 serves 有交集就选上，逐个 `tools/add_subsys.py <子系统> 暂存草稿 --board <板名>` 装进去（一个都没匹配就写最小 project.yaml）；再 gen_project 预览。界面列出选了哪些子系统、哪些能力没有现成子系统（ui.* / link.* 由 io 层接，不列）要用 new_subsys 新建。确认只补题目目录里没有的文件。板名按板卡 schema 规整（小写、只用字母数字和 -）。

真改 Keil：生成确认之后才出现“改 Keil 工程…”，点了显示要改的 .uvprojx 和备份路径（<x>.uvprojx.bak），再点“确认修改”才跑（op flow_accept step=keil，confirm_uvprojx 必须等于要改的路径，否则拒绝）。

机械（docs 09、21）不在这条流程里。

## 评分页（逐项验收 + 存证据）

右栏“评分”（只在评分页显示）。侧车 `dzbench/scoring.py`，op `score_items {path?}` / `score_save {code, item, layer, runs, summary}`。

- **评分项**：读 requirements.yaml（默认当前 app.yaml 旁边的，否则 examples/ 下第一个；下拉可换）。矩阵四列照搬 DS-land-and-air《D题 V23 联调与计分矩阵》：评分项（编号 · 分值 · 原文）| 自动判定（评分项或 metric 上 accept 指向的 app.yaml accept 规格）| 人工 / 物理证据（metric.how）| 当前结论。结论默认 **未验收**；跑满 N 轮全过，仿真 / 台架层写“…通过（未现场验收）”，只有选“现场”层才写“现场通过”。
- **跑一轮**：点“开始一轮”再点“结束这一轮”，或开始方式选“遥测条件”（通道 + 比较 + 阈值，成立开始计时、不再成立或满“最长”秒结束）。结束时截取这段曲线，用 accept.ts（与 accept.py 同一定义）判到位：到位用时、到位后最大误差、没过的原因。设定值取该通道画在同一格的设定值通道；没有就用 metric.value 当常值目标。
- **最差 N 轮**：N 默认规格的 runs（没写就 3），按最差一轮给结论。
- **存证据**：`tools/req.py newlog` 建 `docs/verify/<题号>/logs/<时间>_task<编号>_<层>/`，写每轮 run_NN.csv（截取段全部通道）、run_NN.png（只画截取的那段，每格标通道名 / 单位，设定值虚线）、result.json，notes.md 追加一段；toast 给出可贴进 requirements.yaml `evidence` 的一行。
- **写回 requirements…**：把这条证据（目录相对路径、层、日期、pass / partial / fail、结论和最差一轮）加到该项 `evidence` 末尾；先显示 diff，点“确认写回”才写（op `score_writeback`，不带 confirm 只预览，带 confirm 要带预览时的 sha）。req.py 的状态（台架通过 / 现场通过）就从这里算。

## 标定向导（标定页）

从上往下做，每一步都只读遥测，不发指令：

1. **极性**：选被控量 y（可选误差 e、控制量 u），“录手推 3 s”（执行器不出力，人往 + 方向推）、“录点动 3 s”（开环小幅 ±u），给出 sensor / err / ctrl / act 四处符号和结论（侧车 `polarity_check`）。方向错先改 dir，别调增益。
2. **循迹黑白 / FOC 对齐 / IMU 零偏**：先勾准备清单（没勾完会问一句），选通道，按段录制（白底 / 黑线、对齐后静止、静止），侧车 `wave_measure` 取平均；算出建议值（黑白中点、编码器零点、陀螺静止均值），波动大会提示“不像静止”。
3. 选“写到参数”，点 **提议写入** → `propose {source:"标定"}`，提议卡出现在本页右边，**采纳后才下发**到板上 RAM；之后到封箱页存 flash / 写回 yaml。参数表里没有对应参数就先在 app.yaml 加。
4. **视觉像素表**：目标放到已知位置，填物理量、录 1 s 加一点，生成 `vis_calib_init` 用的 px / val 两张表（贴进固件，不是参数）。

清单整理自 MICU-auto-embedded `refs/control-loop-sign-debug.md`、`foc-calibration-checklist.md`、`attitude-init-single-frame.md`；“先过准备清单再开录”参考 PID_Helper `IdentificationPrepPanel.tsx`。[仿真] 界面截图；[未测] 真板上没走过一遍；循迹阈值按原始读数中点算，固件 line_sensor 用归一化 on_thr 时直接填 0.5；FOC 零点只是录编码器原始角，没换算电角度 / 极对数。

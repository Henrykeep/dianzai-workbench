# 30 验收、单位标定与串级分层（schema 驱动，任何题目通用）

界面和侧车代码里**没有任何题目字段名**：三样东西都写在工程 yaml 的 `link:` 段，由 `tools/gen_link.py` 原样带进
`link_schema.json`（**不进 schema 哈希**，改了不用重烧固件），界面按 schema 渲染。2026H 只是第一个例子，
另外在 car_2wd（标定 + 验收）和 line_car（串级 + 验收）上验证过，截图见下。

## 1 单位标定 `cal`（字段级）

```yaml
- { name: cam_x_px, type: int16, unit: px, cal: { unit: cm, pts: [[0, 0], [600, 100]] } }
- { name: spd_a, type: float, unit: rps, cal: { unit: cm/s, pts: [[0, 0], [1, 20.42]] } }
```

- `pts`：`[原始值, 物理值]`，至少两点、原始值互不相同；`mode: linear`（默认，多点最小二乘直线）或 `piecewise`（分段线性，两端外推）。
- 设定值字段（`ref_for`）没写 `cal` 时继承被控量的，曲线和虚线同单位。
- 只影响示波/测量/读数/台账/验收；“原始”视图仍是线上的原始帧；侧车的阶跃分析/调参护栏仍按原始单位（比例量，不受影响）。
- 数从哪来要写在注释里：2026H 仿真是 `io/sim_setup.c` 的 600 px/m，**真机必须用 O、±5 cm 等多点实测重标**；car_2wd 是 `app_main.c` 里的轮径 0.065 m。

## 2 验收规格 `accept`（评委口径）

```yaml
link:
  accept:
    - { name: 静态定位, y: cam_x_px, band: 1, vmax: 2, hold_s: 0.3, t_max_s: 5, runs: 3 }
```

| 键 | 含义 |
|---|---|
| `y` | 被控量字段（必须有 `ref_for` 指向它的设定值） |
| `band` | 到位误差带，**物理单位**（= 该字段 `cal.unit`） |
| `vmax` | 可选：到位还要求 \|速度\| ≤ vmax（单位/s，100 ms 窗口差分）。题目没给数就别填 |
| `hold_s` | 连续满足多久算到位，默认 0.3 |
| `t_max_s` | 可选：第一段起点到最后一段到位的总限时 |
| `runs` | 台账按最近 N 轮的**最差一轮**汇总，默认 3 |

判定定义（`app/ui/src/accept.ts` 与 `app/sidecar/dzbench/accept.py` 同一定义，两边测试共用 `app/sidecar/tests/accept_vectors.json`，期望值按定义手算）：
设定值每变一次开一段（多目标 = 多段，如 O→+5→−5）；窗口里设定值没变 = 一段保持任务。到位时刻 = 进入并保持满 `hold_s` 的那一刻（秒表能确认的时刻，偏保守）。
到位后误差 = 进入时刻到段末的 max|e|。通过 = 每段到位 && 到位后误差 ≤ band && 总用时 ≤ t_max_s。

界面：读数条先显示 **验收 通过/未过（原因）· 到位 s · 到位后误差**，再留超调/调节做调参参考；台账列 判定/到位/误差/超调，表头一行“最近 N 轮：通过 k · 最差到位 · 最差误差 · 达标”。

注意：一轮 = 两次 t0 之间（按 T 或点“阶跃实验”）。工作台的阶跃实验先回到 low 再跳 high，**回 low 那段也算一段**——`pre_s` 太短时会判“第 1 段没到位”。这是如实判定，不是 bug：要按题目判，就让一轮只包含题目要求的设定值序列（固件里按题目跑测试项，或把 pre_s 调够）。

## 3 串级分层 `loops` 与调法

```yaml
link:
  loops:            # 内环在前
    - { name: 轮速, y: spd_a,   gains: [kp, ki],           note: 内环 }
    - { name: 循线, y: line_mm, gains: [kp_line, kd_line], note: 外环 }
```

界面台账标题栏出现“层”下拉：选一层后读数/验收换成这层的 y，参数面板只列这层的增益（筛选框写 `=kp =ki`，Esc 清掉），**台账每层一本**（只列在这层做的轮次）。

调法（顺序来自 docs/参考来源.md 里的 2026H 资料与串级 PID 通用做法；是方法，不是指标）：
1. **从最内层开始**，外环断开或给固定设定值。选内层 → 做阶跃 → 只动这层增益，直到台账最近 N 轮稳定（不振荡、无持续误差；有该层 accept 就看“达标”）。
2. 内层带宽要明显高于外层（经验上几倍以上），否则外层调不动；扫频（`run_sweep_test`）能给出闭环带宽。
3. **内层不稳不进下一层**。进外层后不再动内层增益；外层出问题先回去看内层台账是否还达标。
4. 每层定稿就“写回默认值”提交一次（一层一个提交，回滚粒度清楚）。

现状缺口（如实）：
- “阶跃实验”按钮用的是 `dzbench.json` 每个工程**一条** `step_tests`，还不能按层选；内层阶跃要固件提供单独给内环设定值的测试项（line_car 目前没有），然后用 T 标记手动做。
- 2026H 只有位置环上报设定值，角度/速度环没有 sp/y 遥测，所以没声明 loops——要分层调，先在固件里把内环设定值和反馈加进遥测。

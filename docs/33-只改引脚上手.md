# 33 只改引脚上手（新队友 30 分钟）

> 目标：不碰 `firmware/`、`apps/`、`examples/` 一行代码，把一块板“换接线”后重新生成，并在电脑上用 host-sim 跑通应用。
> 本文每条命令都在 Linux（Python 3、gcc，无 arm-gcc、无 CubeMX）上实际跑过（2026-10-31，Asia/Shanghai，分支 docs/onboarding）。**真板烧录、Keil、Windows 均【未验证】**，那部分见 [28 换板清单](28-30分钟换板清单.md)、[14 Keil](14-Keil工作流.md)、[15 CCS](15-CCS工作流.md)。

## 规矩（先读，1 分钟）
- **只改**：`boards/<你的板>/` 下的 `.ioc` / `.syscfg` / `board.yaml` / `aliases.yaml`。
- **不改**：`firmware/`、`apps/`、`examples/`、`ports/`。觉得非改不可 = 走错路，先问人。
- 电机反转、编码器反向：改 board.yaml 极性字段或 .ioc 交换引脚，**不在代码里取反**。

## 第 1 步：先在电脑上跑起来（5 分钟，不要板子）
```sh
make BOARD=host-sim APP=motor_speed_demo
make BOARD=host-sim APP=motor_speed_demo run ARGS="2"     # 仿真 2 秒
```
看到这样的文本遥测就对了（转速 spd 追设定 sp）：
```
t=20 sp=2000 spd=0 out=219 err=0
t=40 sp=2000 spd=267 out=254 err=0
```
- `ARGS` = `仿真秒数 [第几秒:命令]...`，例如 `ARGS='3 1.5:S-1.5'`（用法写在 `ports/host-sim/main_host.c` 开头）。
- `APP=car_2wd` 也能跑，但它输出的是二进制帧（给工作台看的），终端里是乱码，属正常。
- `make run` 只支持 `BOARD=host-sim`；真板用 Keil/CCS 或 `make flash`。
- 首次编译约 15 秒（会编全部 firmware 模块）。

## 第 2 步：复制一块最像的板（2 分钟）
```sh
cp -r boards/stm32f103c8t6-car-cubemx boards/my-board   # 板名只能小写字母/数字/-（schema 要求），中文名会被拒
sed -i 's/^name: .*/name: my-board/' boards/my-board/board.yaml
```
选哪块起步见 [28 的板卡表](28-30分钟换板清单.md#各板的最小例程2026-10-29-本机编译结果全部-未测-上板)。STM32 新板只走 `stm32-cubemx`（`stm32f4-hal` 已冻结，新板会被拒）。

## 第 3 步：改引脚（10 分钟）
**正常做法**：CubeMX 打开 `boards/my-board/cubemx/*.ioc`，按实际接线挪引脚，**User Label 保持逻辑名**（`GPIO_LED`、`PWM_MOTOR_A`…，规则见 [05](05-CubeMX工作流.md)），然后**点 GENERATE CODE**。

然后让工具从 .ioc 反推板卡表：
```sh
python3 tools/ioc_import.py boards/my-board/cubemx/f103car.ioc --out boards/my-board/board.yaml --base boards/my-board/board.yaml
python3 tools/validate_board.py boards/my-board/board.yaml      # 0 错误；警告要读
make BOARD=my-board APP=port_selftest gen                       # 生成 build/my-board/gen/board_gen.{h,c}
```
实测：把 LED 从 PA8 挪到 PA12，`board.yaml` 里 `pin: PA12`，`board_gen.h` 里仍是 `RES_GPIO_LED`——应用代码靠逻辑名找资源，所以一行不用改。

### 忘了点 GENERATE CODE 会怎样（实测）
`make check` 里的 `python3 tools/check_gen_consistency.py` 会拦下来：
```
✗ my-board: .ioc 里 PA12 是 GPIO，但 MX_GPIO_Init 没初始化它——改完 .ioc 后在 CubeMX 里点 GENERATE CODE
✗ my-board: MX_GPIO_Init 还在初始化 PA8，.ioc 里它已不是 GPIO（残留旧引脚）……
```
看到这两行就回 CubeMX 点生成，**不要手改 `Core/`**。

MSPM0 把 .ioc 换成 `.syscfg` + `tools/syscfg_import.py`，见 [10](10-SysConfig工作流.md)。

## 第 4 步：常见警告怎么读（3 分钟）
| 提示 | 意思 | 怎么办 |
|---|---|---|
| `.ioc 没写 RCC.HSE_VALUE … 按默认 8000000 Hz` | CubeMX 只存非默认值 | 对照晶振丝印，不一样就在 CubeMX 里改 |
| `[坑脚] PB4 上电默认是 NJTRST` | 调试口复用 | CubeMX SYS → Debug 选 Serial Wire |
| `TODO toolchain.openocd_interface` | 没填烧录器 | 用 Keil/CCS 烧可以不填 |

## 第 5 步：提交前（5 分钟）
```sh
make check
```
- 只提交 `boards/my-board/`；`build/` 不入库。

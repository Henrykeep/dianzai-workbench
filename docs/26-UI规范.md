## 1. 原则（17 条）

| # | 原则 | 来源 | 为什么有效 |
|---|---|---|---|
| P1 | 层级先靠表面明度，再靠线条；全局只用 3–4 级灰（plot < chrome < raised） | Saleae 取色、Grafana、Apple | 人眼先读亮度块，再读线条；线条多了就成噪声 |
| P2 | 结构要能感觉到，但不必看见：分隔线少而淡（只比相邻面亮 3–5%） | Linear 2026、Refactoring UI | 每一条线都在争注意力 |
| P3 | 没赢得的注意力不要去争：导航和 chrome 调暗，数据最亮 | Linear 2026 | 用户的工作对象是曲线和参数 |
| P4 | 灰阶从一个 base 加 contrast 生成，且在感知均匀的空间里（OKLCH）；灰里不掺 accent | Linear 2024 | 明暗主题和高对比主题都能保持一致，避免"脏蓝灰" |
| P5 | 每一级灰都有固定语义（bg / 组件 / 边框 / 文字二级 / 文字一级） | Geist | 杜绝随手取 hex，这是 B 版的根因 |
| P6 | UI 正文 13–14px 无衬线；mono 只用于数字、标识符和代码；数字用 tabular | Geist | v3 全部用 mono，导致"终端感"和噪声 |
| P7 | 层级靠字重和颜色，不靠字号和大写；最多 3 个字号 | Refactoring UI、Apple | 字号阶梯一多就显得廉价 |
| P8 | 量纲不同的量不共用一根轴：每通道一条 lane（small multiples），共享时间轴 | Tufte、Saleae、Grafana | v3 把 ° 和 u 叠在一根轴上，读数是错的 |
| P9 | 每个通道自带 scale 和量程标注，固定显示在 lane 边缘 | Keysight、R&S、Saleae | 不必看图例就能读出数值 |
| P10 | 时间轴采用"锚点加相对偏移"，锚点就是实验事件（阶跃 t0） | Saleae | 调参关心的是"阶跃后多久" |
| P11 | 网格是背景（约 50% 强度），trace 1.5px，无填充无发光；通道色只用于 trace 和标记 | Keysight、Tufte、Grafana | data-ink |
| P12 | 测量绑定在波形上：区间带加光标，侧栏数值注明来自哪条通道、哪个区间 | Keysight Meas、Saleae M0 | 数字和图之间的对应关系一眼可见 |
| P13 | 历史结果用降亮度叠加（余辉），不另画一张图 | Keysight persistence | 对比上一次实验不需要切页 |
| P14 | 侧栏一次只展开一个面板（icon rail） | Saleae、VS Code | v3 右栏 4 段平权、相互竞争 |
| P15 | 动作就近：视图动作放在视图标题栏，全局动作放在顶栏；高饱和色全局只给 1 个主动作和 1 个危险动作 | VS Code 工具栏作用域、Saleae Start | 颜色稀缺才有意义 |
| P16 | 状态栏左边全局、右边当前对象 | VS Code | 符合肌肉记忆 |
| P17 | 对齐和刻度：间距取 4 的倍数，行高 28 / 24，所有列基线对齐 | Linear 对齐、Refactoring UI | "用几分钟后能感觉到" |

## 3. v4 原则→设计决定
| 原则 | v4 决定 |
|---|---|
| P1 表面明度分层 | 只用三级表面：plot L.135、bg L.175、raised L.205。lane 标签列用 raised、绘图区用 plot，不加描边（照 Saleae 的 #090909/#111112/#1c1d1f） |
| P2 结构可感不可见 | 区域之间只留 1px 缝，缝的颜色是 line L.255；去掉面板头下线、行线和右栏 5 条分隔线，只保留 lane 间线和 sec 间线 |
| P3 不争注意力 | 左 rail 和顶栏用 bg，图标 t3；曲线和实时值最亮 |
| P4 生成式灰阶 | gen_tokens.py 从 OKLCH 的 base hue 255 / chroma .005 和 contrast 出发生成两套主题，灰里不掺 accent |
| P5 灰阶语义 | plot/bg/raised/hover/line/line2/t3/t2/t1 九个槽，不再手写 hex |
| P6 字体分工 | UI 用 Inter 13px；数值、标识符、单位用 Geist Mono 12px tabular |
| P7 三个字号 | 字号只有 13 / 12 / 11（11 只用于刻度和角标）；层级靠 500 字重和 t1/t2/t3 |
| P8 small multiples | arm_deg、pend_deg、u 各占一条 lane，各有量程，共享时间轴 |
| P9 每通道 scale | 标签列依次放色条、名称、实时值、/div，以及设定值和余辉来源；lane 内标出上限、零点、下限 |
| P10 锚点时间 | 标尺写作 "t0 · 阶跃 #3"、+0.2 s… |
| P11 网格做背景 | 网格 L.205，零线 L.30；trace 1.5px，无填充无发光 |
| P12 测量绑定 | A/B 光标之间画区间带（6%），标出 Δ0.290 s；测量面板逐条标出来源通道色，并写明"差值相对 #2 · 来源 arm_deg" |
| P13 余辉 | 上一次实验（#2）画成 1px、t3 色、45% 透明的叠线 |
| P14 一次一个面板 | 右栏用 测量/历史/Agent 三个 tab，Agent 用徽标提示有新提议 |
| P15 动作就近、颜色稀缺 | 全局主动作只有"▶ 运行阶跃"（绿），危险动作只有"急停"（红描边）；视图动作放在各自 view header；accent 蓝只用于 dirty 参数、下发和采纳 |
| P16 状态栏 | 左边放侧车、schema、RX，右边放 REC 和当前文件 |
| P17 刻度 | 行高 28、按钮 28、头部 32、间距取 4 的倍数，数值列右对齐 |


## 3.5 落地状态（2026-10-29，截图 shots/redesign/impl/s2_*.png）
已实现：v4 网格（顶栏/图标栏/示波+停靠参数/侧栏/状态栏）、OKLCH 灰阶 tokens（深浅两套）、每通道一条 lane（uPlot.sync 联动光标，首条带相对时间刻度）、lane 标签（名称+4 位有效数字读数+单位+范围）、参数表（名称/值/板上/范围条/默认/说明，脏行 旧→新）、底部停靠页签（参数/快照/板端）、侧栏页签（通道/Agent，带提醒点）。
取舍：
- 示意稿的 setpoint 叠在被控量 lane 上（虚线）——没做：需要 schema 声明“sp_x 对应 x”，不想按命名猜（顾全大局）。现在 setpoint 自成一条 lane。
- 侧栏“测量”页（超调/调节时间）没做成常驻：数值来自 Agent 阶跃分析，单独一页会多为空；留在 Agent 结果卡里。
- 字体换 Inter + Geist Mono（@fontsource 打包，离线可用）；CJK 仍走系统字体。
未实现：/div 刻度、余辉、t0 阶跃锚点、A/B 光标与 Δ 带、历史页、高对比度主题；1280×800 只有一条 @media 兜底，未截图。

## 4. 实现约束（核心保持通用）
- lane、量程、单位、设定值全部来自 schema 的通道定义；不为某个题目写专用 UI。
- 灰阶由 base / contrast 生成（gen_tokens.py 的规则），组件只引用语义槽。

## 3. 两个版式
**A · 仪表（shots/redesign/a_instrument.png，21 个控件）**——照 Foxglove：顶栏 48（连接胶囊、pin 状态、⌘K、REC、急停）＋ 左 248 通道（实时值 + 本轮实验指标卡）＋ 中间曲线（曲线/原始/频谱 标签、时间窗、暂停）＋ 右 340 分页（参数 / 实验 / Agent）＋ 状态栏 26。优点：和现在的功能一一对应，迁移风险小；缺点：参数和 Agent 不能同时看。

**B · 调参工作流（shots/redesign/b_workflow.png，18 个控件）**——照 Linear / VS Code：左 52 活动栏（实时 / 调参 / 回放 / 工具 / 设置）＋ 中间上方曲线、图例带实时值、下方“实验结果 + 增益滑条”一条＋ 右侧 Agent 抽屉（可关）。围绕“看曲线 → 改一个增益 → 重跑”这个主循环；Agent 的建议卡直接给“采纳并重跑阶跃”。优点：主任务一屏完成、最像“专业工具”；缺点：改动大，原始 / 频谱 / 串口细节要放进其他页面。

## 5. v5「调参台」：学原则，不学长相（2026-10-29，示意稿 /workspace/shots/redesign/v5/dark.png、light.png，生成器 gen.py）
用户反馈 v4“像 Saleae/Grafana 的翻版，还不够高级”，还要求“要有工作台的样子”。v5 只从参考里拿**为什么好用**，长相全部从本场景推出来：电赛调参就是“改参数 → 打阶跃 → 读指标 → 再改”的闭环。
硬性验收：一眼看出是**操作台**：面板停靠、控件伸手可及、按“连接 → 调参 → 阶跃 → 判读 → 定稿”的顺序走，不能做成展示用的仪表盘。

| 决定 | 借的原理（出处与原因） | v5 的原创落地 |
|---|---|---|
| 版式＝工作流：左边参数（输入）、中间实验（过程）、右边改动单（建议），顶栏五站状态 | Fitts / 工作流就近（Bret Victor《Inventing on Principle》：改动和结果要挨着，看得见因果）；Logic Pro / 调音台的“信号从左流到右” | 五站做成机柜铭牌式的状态位，不是向导：每站显示自己的实时状态（如“1 项待下发”“#7 已完成”），当前站用黄铜底线标出 |
| 颜色分两类语义：**黄铜＝意图**（设定值、待下发、提议、主按钮），**冷色＝实测**；红只给急停和越限 | Tufte“最小有效差异”加前注意加工（Ware《Information Visualization》）：只用一个色相维度承载一个问题，扫一眼就能分出来；Grafana/Saleae 的“颜色稀缺”原则 | “你想要的”和“它实际做的”分成两种色温，这是本工具独有的问题，不是哪家的配色；暖石墨底呼应黄铜，不用冷蓝灰，也不用紫 |
| 指标直接画成**工程制图尺寸线**（Mp 竖向、tr/ts 横向，带箭头和引出线），±5% 容差画成走廊 | Tufte“数据和标注合一”（把注释直接写在图上，眼睛不用在图和表之间来回）；ISO 129 尺寸标注就是工程师最熟的读法 | 电赛学生都学过制图：Mp、tr、ts 的定义（Ogata）直接以尺寸的形式出现，比旁边放一张表更能教会人怎么读阶跃响应 |
| 参数行带**刻度尺**：板上值（灰杆）、新值（黄铜杆加改动区间）、上次通过（绿菱形） | 实体仪表的刻度盘：位置记忆比数字快（Norman《设计心理学》：把知识放在世界里，而不是记在脑子里） | 一行里同时看到“在哪、要去哪、上次好的在哪”，调参时不用翻历史 |
| 底部**运行台账**：每轮一列，写明改了什么，列出 Mp/tr/ts/ess 和判定，余辉轮虚线、本轮实线 | 实验记录本 / 受控变量法（“一次只改一个量”）；小倍数（Tufte small multiples）用于横向比较 | 把“科学实验”的写法做成界面：每列只有一个改动，因果一目了然；判定阈值写在表头，不藏在设置里 |
| Agent 输出是**改动单**（基于哪一轮、改哪个参数、实测 vs 采纳后预计、理由、护栏），采纳只改参数表，不直接下发 | 代码评审的 diff 思路（GitHub PR：先看改动再批准）；人在回路（Sheridan 自动化等级 5：建议 + 人批准） | 黄铜左边线和虚线分割的票据样式，告诉你它是待批的单子，不是聊天消息 |

按症状排查
    症状表整理自 MICU-auto-embedded troubleshooting.md，分类用 failure-taxonomy.md。
    
    
    自检
      ✓ 正常　! 部分功能不可用　✗ 必须处理。命令行同样：python -m dzbench --doctor
      
      
      赛前检查
          
        
          板上参数要等于固件默认值：调好的值先“定稿”重烧，不然一复位就丢。人工项（电池、螺丝、线束…）在导出的清单里打勾。
          
        
          
      
        
          
          
          调试探针
          
          
          烧录、烧前备份、ELF 变量实时读取都走这里选的后端。存本机 ~/.dzbench/machine.json（不进 git）；工程 dzbench.json 写了同名键时以工程为准。
          
          
          
          
          
            
          
            
          
            
        
            
                  
      
        
            
          
            协处理器部署（SSH）
            
          
            只走 SSH 密钥登录（先在终端 ssh-copy-id 用户@IP），不存密码。设置存本机 ~/.dzbench/machine.json。程序后台跑，输出在远端目录 dz.log。
            
          
          
          
          
          
          
          
          
          
          
            
          
            
          
            
        
            
                  
      
        
            
          
            串口线控（DTR / RTS）
            
          
            勾上 = 线有效（多数 USB 转串口芯片上是引脚低电平）。改了马上生效，自动重连 / 下次打开沿用。复位 / 进 BOOT 按常见一键下载接法（ESP32：esptool 时序；STM32：DTR→NRST、RTS→BOOT0），板子接法不同会反着来，先在不怕复位的时候试。
            
          
          
          
            
          
            
          
          
            
          
            
        
            
                  
      
        
            
          
            调参前问答
            
          
            先说清对象和底线，Agent 再出初值。超调上限 / 保守步子会收紧调参护栏（只收紧不放宽）；“还有什么”里写“不能反转”“超调不超过 5%”这类话，规则会认出来。
            
          
            
          
            
        
            
                  
      
        
            
          
            大模型设置
            
          
            任何 OpenAI 兼容接口都行。Key 只存在本机 ~/.dzbench/config.json（权限 600），不进仓库、不回传界面。没网时“分析阶跃”照样能用。
